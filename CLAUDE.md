# TTierList — контекст проекта

## Общение
- Отвечай только на русском, коротко и по делу, без теории ради теории.
- Окружение: Windows, PowerShell, IntelliJ IDEA. Команды давай в формате PowerShell (`.\gradlew.bat`, а не `./gradlew`).
- Код пиши целыми файлами, не проси пользователя править код вручную.
- Не додумывай данные: если чего-то не хватает для вывода, спроси.

## Что это за проект
Локальное приложение для тир-листов в стиле https://tiermaker.com/.
Стек: Java 21, Spring Boot 3.4, Gradle, Thymeleaf, H2 (файловая база), Bootstrap и SortableJS с CDN.
Репозиторий: https://github.com/7VeDMaK/TTierList (перенесён с GitLab). Имя Gradle-проекта — `ADList`, пакет `adlist`.
Запуск: `.\gradlew.bat bootRun`, затем http://localhost:8081/cards

## Как пользователь работает с приложением
1. Хранит картинки на компьютере и загружает их пачкой (`/fileSystemMany`): из каждой картинки создаётся карточка в тире UNDEFINED.
2. Редактирует каждую карточку: имя, описание, ссылка, теги.
3. Раскладывает карточки по тирам перетаскиванием.

Страницы:
- `/cards` — режим просмотра: попапы при наведении, поиск по имени, фильтр по тегам.
- `/cards/info` — режим перетаскивания (SortableJS, сохранение через `POST /cards/reorder`).
- `/cards/{id}` — страница юнита (детали карточки).
- `/cards/new`, `/cards/edit/{id}` — создание и редактирование.
- `/cards/bulk-edit-tags` — массовое редактирование тегов.
- `/tags` — управление тегами.

## Приоритеты пользователя
- Дизайн похож на TierMaker. Минимализм: ничего лишнего, всё ровно выставлено, без перегруза информацией.
- Удобная система карточек: перетаскивание, редактирование, теги.
- Возможность делиться тир-листом с другими как полноценным интерактивным приложением, а не скриншотом.
- Конечный получатель — случайный человек, не программист. Поэтому никаких «корпоративных» технологий (Docker, PostgreSQL, серверы). H2, относительные пути и простота запуска — осознанный выбор, не менять.

## ДАННЫЕ — КРИТИЧНО
- База: `db/data.mv.db`. Картинки: `src/main/resources/static/css/uploads/`.
- Ни то, ни другое не лежит в git. Это единственная копия данных пользователя.
- Никогда не удалять, не перемещать и не перезаписывать эти папки и их содержимое без явного подтверждения пользователя. Не запускать `git clean`.
- Перед любой работой, затрагивающей файлы картинок или схему БД, предложить сделать бэкап.
- `spring.jpa.hibernate.ddl-auto=update`: при изменении сущностей следить, чтобы существующие данные не терялись.
- Приложение не должно быть запущено в двух экземплярах одновременно (H2 блокирует файл).

## Принятые решения
- Обмен тир-листом — через экспорт в один самодостаточный HTML-файл:
    - Эндпоинт `/export` и кнопка «Экспорт» на главной странице.
    - Данные (карточки, тиры, позиции, теги, описания, ссылки) вшиваются в HTML как JSON.
    - Картинки сжимаются примерно до 300–400px по длинной стороне и вшиваются как base64. Оригиналы у пользователя не трогаются.
    - Внутри файла: режим просмотра (попапы, поиск, фильтр по тегам) и страницы юнитов (отдельный экран внутри того же файла, кнопка «Назад» браузера работает).
    - Перетаскивание для получателя пока не делаем, может быть добавлено позже (изменения только в браузере получателя). Редактор в экспорт не переносим.
    - Файл — снимок на момент экспорта: обновил у себя — экспортировал заново.
    - Размер ориентировочно 5–8 МБ на 100 карточек; сжатие обязательно.
- Jar/exe как способ раздачи не используем. Jar остаётся только для личного запуска.
- Слои, типы id (`Integer` в сущностях против `Long` в репозиториях), `@Data` на сущностях, заглавные имена пакетов — не приоритет, трогать только попутно и только если это безопасно.

## План работ
Каждый этап — отдельный коммит в ветке `refactor`. После каждого этапа собрать, запустить и проверить страницы.

1. **Чистка мёртвого кода и сборки** (без изменения поведения):
    - удалить `TestController`, `TagService`, `dto/CardTagUpdateDTO`, `dto/CardTagUpdateWrapper`, `docker-compose.yml`, `HELP.md`;
    - переименовать `CardImageCotroller` → `CardImageController`;
    - убрать `rowIndex` из `Card`, `resizeImage` и неиспользуемые импорты из `CardService`, неиспользуемые методы репозиториев, `extractCardId`, лишние атрибуты модели;
    - вынести дублирующуюся группировку по рангам в `CardController` в один метод;
    - убрать `console.log` из фильтра в `cards.html`;
    - из `build.gradle` убрать bootJar-копирование, задачу `copyDbFile` и закомментированную зависимость postgres;
    - добавить в `.gitignore` `/db/` и `src/main/resources/static/css/uploads/`;
    - написать короткий `README.md`.
2. **Починка того, на что опирается экспорт:**
    - загруженные файлы сохранять под уникальными именами: сейчас файл с уже существующим именем молча не загружается при пачечной загрузке, а при редактировании карточки обнуляет её картинку (`uploadImageToFileSystem` возвращает `null`). Существующие картинки и записи в БД должны продолжить работать;
    - отдача картинок: правильный `Content-Type` вместо всегда `image/png`, 404 вместо 500, если файла или записи нет;
    - `/fileSystemMany` в `@RestController` возвращает строку `"redirect:/cards"` текстом вместо редиректа;
    - `POST /cards/new` и пачечная загрузка падают с 500 на дубликате имени карточки (unique constraint), пачка обрывается посередине.
3. **Экспорт в HTML** — как описано в разделе «Принятые решения».
4. **Единый стиль всех страниц** по образцу главной страницы тир-листа (`/cards`):
    - вынести общие цвета, шрифты и кнопки в `common.css`, применить ко всем шаблонам;
    - поправить перепутанные надписи кнопок режимов (на `/cards` кнопка «Info mode» ведёт в drag-режим, на `/cards/info` кнопка «Drag mode» ведёт обратно);
    - экспорт должен использовать тот же стиль.
5. **Контент и улучшения** — по списку пользователя. Уже известные кандидаты:
    - bulk-edit тегов не снимает теги: карточка без галочек не попадает в `tagPairs`; если снять все галочки на странице — 400 (параметр обязателен). В форме уже есть скрытые поля `cardIds`, их можно использовать;
    - поиск: `convertRussianToEnglish` переводит кириллицу в латиницу по раскладке, поэтому поиск по русским названиям, вероятно, не работает; `matchesAllLetters` не учитывает порядок букв. Уточнить у пользователя, что задумано;
    - новые карточки получают `position = 0`, порядок внутри тира не определён до первого перетаскивания;
    - тиры захардкожены в enum `Rank` (SSS, AAA, BBBP, BBBN, CC, DD, FFF, UNDEFINED) — возможный переход на настраиваемые тиры обсуждать с пользователем отдельно.

## Правила работы с git
- Ветка `refactor`, `main` остаётся рабочим.
- Не переписывать историю и не делать `reset --hard` / `push --force` без явной просьбы.
- Сохранять переводы строк файлов как есть (в проекте смешанные CRLF и LF).
- Перед изменениями показывать план, после — кратко, что сделано, и коммит.
